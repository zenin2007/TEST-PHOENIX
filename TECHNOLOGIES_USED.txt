3. CORE SELF-HEALING ENGINE (TESTPHOENIX ENGINE)
================================================================================
• Microsoft Playwright (Python Synchronous API `sync_playwright`)
  - Headless Chromium browser automation.
  - Live page evaluation, synthetic user actions (click, fill, wait), and network monitoring.

• Live DOM & Accessibility Tree Inspector (`dom_inspector.py`)
  - JavaScript evaluation injected directly into browser execution contexts.
  - Dynamically extracts interactive elements: `button`, `input`, `textarea`, `select`,
    `[role="button"]`, `[role="link"]`, etc.
  - Computes bounding boxes, computed accessibility roles, accessible names, visible text,
    placeholders, aria labels, nearby labels, form associations, and DOM parent trees.

• 5-Factor Mathematical Scoring Engine (`scoring.py`)
  - Normalizes scores strictly between 0.000 and 1.000:
      Score = (0.40 * Semantic Intent)
            + (0.20 * Accessibility Role)
            + (0.15 * Visible Text)
            + (0.15 * Context Clues)
            + (0.10 * Structural Hierarchy)
  - Built-in multi-domain synonym cluster dictionaries:
    * Task Management: `create` ~ `add` ~ `new`, `task` ~ `item` ~ `work item`, `submit` ~ `save`
    * E-Commerce: `checkout` ~ `proceed to payment` ~ `place order`, `cart` ~ `bag`, `customer` ~ `recipient`
  - Lexical stop-word filtering prevents ratio dilution.

• Autonomous Safety Gating System:
  - Confidence Threshold Gate: Candidates scoring < 0.75 are rejected immediately.
  - Ambiguity Margin Gate: When top candidate score minus runner-up score is < 0.15,
    engine halts safely and marks test as `HUMAN REVIEW REQUIRED`.
  - Interactability Gate: Disabled or obscured elements rejected.
  - Genuine Defect Preservation: HTTP 500 server crashes suppress UI healing, ensuring
    real bugs are never masked.

• Dual-Verification Engine:
  - Outcome must be confirmed in both the frontend UI DOM and backend SQLite database
    before certifying a test step as `SELF-HEALED`.

4. DATABASE & PERSISTENCE LAYER (ZERO FIREBASE)
================================================================================
• SQLite 3
  - Embedded, serverless, zero-configuration relational database engine (`backend/tasks.db`).
  - ACID-compliant transaction integrity.
  - 100% local, offline-capable, private, and deterministic.

• Database Tables:
  1. `tasks`: Development tasks with status, assignee, and timestamps.
  2. `orders`: E-commerce orders with product, customer name, price, quantity, status.
  3. `test_runs`: Execution history, durations, selectors, verifications, diagnostics JSON.
  4. `healing_memory`: Persistent cache of verified locator mappings:
     `{original_intent, original_locator, recovered_locator, fingerprint, confidence, verified, timestamp}`.

• Zero Firebase Constraint:
  - NO Firestore, NO Firebase Auth, NO Firebase Realtime DB, NO Firebase Hosting.
  - Completely self-contained architecture.
